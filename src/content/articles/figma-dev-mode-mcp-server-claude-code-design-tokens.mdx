This workflow comes from developer Vishwas Gopinath's post on Builder.io's blog, connecting Claude Code directly to Figma's Dev Mode MCP server. His original write-up used Figma's first setup method, a local server reached over SSE. Figma has since changed the recommended setup to a plugin-based flow, and added a separate hosted remote server option, so the steps below follow Figma's own current documentation rather than reproducing Gopinath's now-outdated commands. The underlying idea, and the reason it's worth doing, is still his.

## The workflow

1. **Understand what this actually gets you.** A plain screenshot or pasted image only shows an AI coding agent what a design looks like. Figma's MCP server instead exposes the file's actual data: variables, components, and layout structure, so code generation can use your real design-token names and existing component mappings instead of guessing at hex values and spacing from a picture. That's the specific gap Gopinath's write-up is about closing.

2. **Set up the remote server (the current recommended path).** In Claude Code, run `claude plugin install figma@claude-plugins-official`, then restart Claude Code. Type `/plugin`, arrow over to the Installed tab, select the Figma server, and press Enter to start authentication, then approve access on the page that opens. Running `/plugin` again should show the Figma server as connected. This route works on any Figma seat or plan, per Figma's own documentation.

3. **Or set up the desktop server, if you'd rather keep everything local.** Open the Figma desktop app with a design file open, switch to Dev Mode, and enable the MCP server toggle in the right sidebar. Copy the server URL it displays, then in Claude Code run `claude mcp add --transport http figma-desktop http://127.0.0.1:3845/mcp` and restart. This needs a Dev or Full seat on a paid plan, per Figma's documentation, and keeps everything running on your machine rather than through Figma's hosted server.

4. **Select a frame and ask for code, not a redesign.** Gopinath's core technique is simple: select a specific frame or component in Figma, or paste its Figma link into your prompt, and ask Claude Code to convert that selection into code. Because the agent can now pull the underlying variables and component data, the output should reference your actual design-system tokens instead of inventing new hardcoded values.

5. **Work frame by frame, and expect to assemble multi-screen flows yourself.** Gopinath is specific about this limitation: the workflow doesn't handle an entire multi-frame user flow in one pass. Convert each frame individually, then assemble the resulting pieces into your actual application structure by hand.

6. **Use a short recording instead of a long prompt when something's wrong.** For revisions or bug reports against generated output, Gopinath recommends a brief screen recording over a lengthy written description, on the reasoning that showing an interaction problem communicates it faster and more precisely than describing it in prose.

## Why it matters for designers

The persistent failure mode in design-to-code handoff isn't that developers can't read a design file, it's that the specific values (this spacing token, that semantic color name, this exact component variant) get silently reinvented somewhere between Figma and the codebase, quietly drifting the two out of sync. Giving a coding agent structured access to the same variables and component data a designer actually set up is a direct attack on that specific failure, not just a faster way to eyeball a screenshot.

For a design-engineer or a developer working closely with design systems, this also raises the bar for what's worth maintaining in Figma itself: components and variables set up carefully now have a second, very literal consumer, since they aren't just documentation for humans anymore.

## What to watch out for

Gopinath's write-up is blunt about the rough edges, and they're still worth taking seriously even though his exact setup steps have moved on: there's no way to surgically patch previously generated code without a fresh regeneration, there's no visual refinement loop after code comes out the other end, and pulling together a multi-frame flow is still manual assembly work, not something the agent does end to end. This is also, as he points out, fundamentally a developer-facing workflow. A designer without a Claude Code environment set up can't run it themselves, which can turn it into another handoff bottleneck rather than removing one.

Treat any generated markup as a draft, particularly for accessibility. Neither Gopinath's post nor Figma's documentation confirms that generated code reliably preserves accessible semantics from the original design, so a manual accessibility pass on generated components isn't optional. And if you're working with client work under an NDA, start with the fully local desktop server rather than the newer hosted remote option until you've separately confirmed how Figma's remote server handles the design data it processes.
