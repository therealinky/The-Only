Figma used its Config India event in Bengaluru this week to move two things forward that change how a prototype gets from the canvas into code: code layers are now in open beta, and there's a new document type called Specs. Both are built around the idea that a coding agent, Figma's own or one you already use, should be able to read your design work directly.

## What changed

**Code layers are open to everyone.** A code layer is a working, code-backed prototype that sits on the canvas next to your frames. Figma's overview says code layers are rolling out in open beta on all plans. You can make one by converting an existing design, prompting the Figma agent, importing a lightweight prototyping codebase from GitHub or a local folder, capturing a live web page with the Chrome extension, or pulling in a prototype from a coding tool through Figma's MCP server. A GitHub import stays connected to its repository, and you can push changes to a branch and open a pull request for review.

**Versions side by side, and a way back to layers.** You can duplicate a code layer, try a different direction, and compare the two on the canvas, then combine ideas from each. An **Extract designs** command turns a screen or flow from a code layer back into editable Figma layers, so a designer can fix things the usual way and send the edits back.

**Specs is Markdown on the canvas.** Press D or use the Specs icon in Figma or FigJam, or drop any .md file onto the canvas. A spec can embed frames, FigJam diagrams, and code layers alongside the text. Agents can read a spec as Markdown, update it, and reply to comments through the MCP server, and pasting a spec's link into a coding agent passes along the linked frames and code. Figma says Specs is rolling out in open beta on web, desktop, and mobile, for paid plans.

**Design systems get guidelines for agents.** Published libraries can now carry guidelines that agents follow, in open beta on paid plans. Code sources, which connect a library to a GitHub repo or npm package, are in closed beta, and a central place to manage all of it is only being previewed.

## Why it matters for designers

The handoff document has always lived somewhere else: a ticket, a wiki page, a comment thread. Specs puts it on the canvas, in a format coding agents already read well, with the actual frames embedded instead of screenshots. If you're already writing a short brief before prompting an agent, this is a more structured home for it.

Code layers matter for anyone who's been prototyping in a separate tool and pasting screen recordings back into Figma. Being able to keep several coded directions next to each other, comment on them like any other frame, and pull a screen back out as layers, closes a loop that's been awkward until now.

## What to watch out for

The free window is short. Figma says code layers use AI credits, and they're only free to create and edit on paid plans through November 4, 2026. After that there's no published rate yet, so keep an eye on your credit usage if you start relying on them.

Figma describes the GitHub import as supporting "lightweight" prototyping codebases and says support for more complex ones will come over time, so don't expect to drop a production app onto the canvas.

Everything here is described as rolling out, with availability varying by feature, so some of it may not be in your account yet. We haven't tried code layers or Specs ourselves; this is based on Figma's own announcements.
