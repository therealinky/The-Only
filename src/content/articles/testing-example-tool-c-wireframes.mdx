We used Example Tool C for a week on a fictional internal project to see how far a text prompt could get us toward a usable wireframe.

## What we did

We fed it short prompts describing common screen types — a dashboard, a settings page, a checkout flow — and compared the output to wireframes we'd sketch by hand for the same brief.

## What worked

For very common patterns, the output was a reasonable starting point: rough placement of a nav, a primary content area, and obvious calls to action. It saved time on the blank-page problem.

## What didn't

Anything with unusual information architecture came out generic. It doesn't ask clarifying questions, so ambiguous prompts produce confident-looking wireframes that don't match what you actually meant.

## Best for

Early exploration and workshop warm-ups where you want something to react to. Not a substitute for mapping user flows first.
